# Шаг 2: неподвижная камера → координаты пола

Открыть **http://localhost:8080/floor.html**. Запуск, как и раньше: `./run.sh`.
Все вычисления выполняются в Docker. Приложение использует текущий результат
intrinsics и его разрешение; первый этап переснимать не нужно.

## Съёмка

1. Закрепите камеру в её окончательном положении. Фокус, зум и кадрирование
   должны совпадать с intrinsics. После начала привязки камеру не перемещайте.
2. Положите плоскую жёсткую доску рисунком вверх на ровный пол. Укажите расстояние
   от пола до поверхности рисунка: толщину основы и листа в миллиметрах.
3. Подключите камеру, подтвердите установку и нажмите «Применить».
4. Поместите доску в место, которое станет началом координат. Подержите её
   неподвижно 1–2 секунды и нажмите **«Сохранить опорное положение»**.
5. Перемещайте и поворачивайте доску в плоскости пола. Перед каждым сохранением
   останавливайте её. Соберите минимум 6, лучше 10–15 положений по площади зоны:
   слева, справа, ближе, дальше. Не ограничивайтесь одной линией. После опорного
   положения доступен автосбор раз в 3 секунды.
6. Нажмите «Рассчитать привязку». При неоднозначности или слабой геометрии добавьте
   другие положения, в том числе ближе к камере. Большую ошибку отдельного положения
   можно проверить, исключить это положение и пересчитать.

Доску **не нужно удерживать на одном месте**, и вводить её X/Y при перемещениях
тоже не нужно. Требуется, чтобы все положения лежали на одной плоскости.
Доску нельзя приподнимать, опирать на препятствия, наклонять или изгибать.

## Система координат

Первое положение задаёт привязку к местности:

- начало — на полу под нижним левым углом печатной сетки, без белого поля;
- X — вправо вдоль строк напечатанной сетки;
- Y — к верхнему краю напечатанной сетки;
- Z — вверх от пола;
- единицы координат и матриц преобразования — **метры**.

Физически отметьте начало и направление осей на полу, если понадобится
восстановить систему после перемещения камеры. Первое наблюдение удалить отдельно
нельзя: для нового начала координат используйте «Новая привязка».

## Дальняя доска

Доска для пола задаётся отдельно от доски первого шага: число маркеров, сторона
маркера и промежуток вводятся в блоке «Камера и доска». Для текущей установки это
AprilGrid **3 × 3, маркер 50 мм, промежуток 15 мм**, рамка 2 ячейки; маркера ID 6
на доске нет, это допустимо.

Издалека чёрная рамка маркера сливается с угловыми квадратиками сетки, и обычный
детектор OpenCV не выделяет маркер как четырёхугольник. Поэтому в режиме пола:

1. Стандартный детектор ищет маркеры на исходном кадре.
2. Собственный поиск четырёхугольников: адаптивная бинаризация и лёгкая эрозия,
   разрывающая диагональные перемычки. Каждый кандидат, включая отклонённые
   детектором OpenCV, уточняется по реальным границам и сверяется с кодами
   маркеров доски в 4 поворотах. Допускается не более 1 ошибочного бита;
   у tag36h11 коды различаются минимум на 11 бит.
3. От найденных маркеров доска достраивается по раскладке: соседей ищут там, где
   их предсказывает гомография, но углы снова измеряются по изображению,
   а код проверяется так же строго.
4. Только если найдено мало маркеров, проверяются увеличенные ×2/×3 копии области.

Углы всегда измеряются на исходном кадре: их не подгоняют к идеальной сетке.

Для одного положения требуются минимум 4 согласованных маркера в двух строках
и двух столбцах. В неподвижной серии из 3–5 кадров берётся медиана измеренных
координат общих углов; движущаяся серия не принимается. В интерфейсе показаны
реальный размер маркеров в исходных пикселях и увеличенный фрагмент доски.

8 пикселей — нижний порог поиска, а не обещание точности. При 10 ячейках на сторону
(6 кодовых + 2 рамки с каждой стороны) короткая сторона 8–10 пикселей уже может
терять биты. Увеличение картинки не возвращает утраченную информацию. Для уверенной
работы желательно хотя бы 15–20 пикселей по короткой стороне маркера. При сильном
ракурсном сжатии нужна более крупная распечатка, более близкое положение или
более высокий/вертикальный ракурс камеры. На текущей установке маркеры 50 мм
в дальнем углу занимают около 32 пикселей и находятся все.

## Что рассчитывается

`floor_geometry.py` решает задачу с фиксированными intrinsics:

- для каждого наблюдения проверяет согласованность углов и находит варианты
  плоской позы через IPPE;
- совместно оценивает одно положение камеры и свободные X/Y/угол каждой позиции
  доски, ограничивая все положения общей плоскостью;
- первое положение фиксирует начало и оси; остальные положения свободны;
- учитывает высоту рисунка над полом;
- проверяет положительную глубину, положение камеры над полом, пространственный
  разброс наблюдений и близкие альтернативные решения;
- возвращает ошибки наблюдений и условную оценку неопределённости.

Используются робастные невязки `soft_l1`. Низкая ошибка репроекции сама по себе
не доказывает точность координат. Неопределённость рассчитана при фиксированных
intrinsics, размерах доски и идеальном плоском полу — ошибки этих предпосылок
в неё не входят. Горизонтальное перемещение камеры нельзя надёжно отличить от
свободного перемещения доски, поэтому физическая фиксация камеры обязательна.

## Результат и проверка

После расчёта появится сетка пола с шагом 0,5 м. Нажатие на изображение вычисляет
координаты пересечения луча с полом. Для точки на высоте (например, маркера на
роботе) сначала введите эту высоту: пересечение с полом иначе даст неверные X/Y.

Проверьте результат на нескольких независимо измеренных точках/расстояниях,
особенно в дальней части рабочей зоны. Около горизонта ошибка резко увеличивается.

Экспорт JSON и OpenCV YAML содержит:

- `T_camera_from_floor`, `T_floor_from_camera` — взаимно обратные матрицы 4×4;
- `plane_equation_camera` — плоскость `n · P_camera + d = 0`;
- гомографии между плоскостью пола и **исправленными от дисторсии** пикселями;
- intrinsics, высоту камеры, толщину доски, ошибки и статус результата.

В JSON также есть позиции доски, условная ковариация и пояснения. Результат с
`valid: false` требует дополнительных наблюдений; координаты по нему интерфейс
не выдаёт. Пример пересчёта пикселя с корректным учётом дисторсии:

```python
from floor_geometry import pixel_to_floor
point = pixel_to_floor([u, v], extrinsics_json, height_m=0.0)
```

Наблюдения и результаты: `data/floor/sessions/<id>/`. Активная привязка:
`data/floor/current.json`. Новая привязка сохраняет предыдущую сессию на диске.
Изменение intrinsics требует новой привязки пола.

Для каждой позиции сохраняется один контрольный PNG из неподвижной серии,
а в JSON — усреднённые координаты углов, число кадров серии и измеренное дрожание.

## Проверки

```sh
docker build --builder default -f tests/Dockerfile -t ext-cam-qa .
docker run --rm -v "$PWD:/work" ext-cam-qa
docker run --rm --network host -v "$PWD:/work" ext-cam-qa python tests/browser_floor_check.py --camera
```

Тесты проверяют восстановление известного положения камеры при свободных
перемещениях доски, пересечение луча с полом и плоскостью на заданной высоте,
маленькие маркеры, один повреждённый бит кода, отказ при движении серии и
сохранность intrinsics. Тест браузера не сохраняет наблюдения пола.
